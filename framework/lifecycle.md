# Integrated lifecycle and gates — SUS-M1/SUS-A1

| Gate | Phase | Exit evidence |
|---|---|---|
| G0 | Concept | Mech/UAV CONOPS, system boundary, initial hazard list, feasibility assumptions |
| G1 | Requirements | Pilot/mission needs, system requirements, interfaces, human factors requirements |
| G2 | Preliminary architecture | Walker architecture, UAV FHA, PHA, actuation/pilot/dock trade studies |
| G3 | Detailed design | SSHA, UAV PSSA, design, power/stability/egress analyses |
| G4 | Bench and simulation readiness | Supported joint rigs, simulation builds, controlled integration tests |
| G5 | Verification and assessment | Test records, fault injection, SHA/O&SHA, UAV SSA and discrepancies |
| G6 | Release | Configuration audit, evidence manifest, safety case, risk disposition and approvals |
| G7 | Change and sustainment | Change impacts, maintenance updates, regression and new release |

The gates are project-defined. Human-in-the-loop and human-occupied testing require additional explicit independent review, physical restraints/supports, egress planning and controlled test authorization. A simulation gate is not permission for human-occupied operation.
