# Software Contribution to System Risk — Section 4.4

## Scope
Walker motion, protective stop, pilot HMI, docking interlocks, integrated command authority, PX4 software and parameters.

## Procedure
1. Identify software-controlled functions and hazardous failure conditions.
2. Link hazards to software causal contributions and interface authority.
3. Evaluate software safety criticality using applicable MIL-STD-882E criteria, distinct from DO-178C assurance levels.
4. Allocate safety requirements and independent protective mechanisms where justified.
5. Analyze timing, state transitions, concurrency, stale data, fault handling and common-cause paths.
6. Define requirements-based tests, fault injection, review and evidence independence.
7. Pin versions, configuration, parameters, toolchain and dependencies.
8. Reassess after changes and anomalies.

**Output:** software safety assessment, requirements, verification evidence, discrepancies and residual-risk links. **Status:** process guidance, not completed assurance.
